# Generator B3D: публикация и Android

Дополнение к существующему сайту Cloudflare Pages `kb911-ru`. Страницы сайта не меняются.

## Настройка Cloudflare

1. Подключить R2 Standard в существующем аккаунте. Cloudflare требует самостоятельно принять условия подписки. Использование сверх бесплатного лимита оплачивается.
2. Создать **приватный** R2 bucket `kb911-3d-temp`. Не включать публичный `r2.dev` и не подключать к bucket публичный домен.
3. Pages → `kb911-ru` → Settings → Production → Bindings: R2 bucket, имя **MODELS**, bucket **kb911-3d-temp**.
4. Variables and secrets: **MODELS_API_TOKEN** (Secret, случайный ключ минимум 32 символа), **PUBLIC_BASE_URL** (Text, `https://kb911.ru`). Ключ не должен попадать в GitHub или исходники.
5. Развернуть ветку с `functions/` и `_routes.json`. После изменения bindings/secrets требуется новый deployment. Для preview не подключать production bucket.
6. Убедиться, что cache rules домена не кэшируют `/3d-temp/*` или `/api/models/*`: API и модели отправляют `Cache-Control: no-store`. Не переопределять этот заголовок правилом Cache Everything.

## Windows

Оставить действующий `LocalViewExport.js`. Использовать `Generator B3D.exe` рядом с B3D, как раньше. Генерация не делает сетевых запросов. После её завершения кнопка «Скопировать ссылку» загружает готовый HTML. Успешный ответ должен содержать ту же SHA-256 и размер; только затем ссылка отображается и копируется. Повторное нажатие копирует готовую ссылку; после ошибки повторяет отправку. Изменение проекта/модели сбрасывает готовую ссылку.

Введите общий ключ API в поле «Ключ публикации», нажмите «Сохранить ключ». Он защищён Windows DPAPI в `%LOCALAPPDATA%/GeneratorB3D/publication-key.bin` и привязан к текущему пользователю Windows. Альтернатива: переменная окружения `KB911_3D_TOKEN`; она имеет приоритет.

Необязательный `Generator B3D.json` рядом с EXE:

```json
{"apiBaseURL":"https://kb911.ru","workRoot":"D:\\_В РАБОТЕ -","project":"","model":""}
```

`workRoot` задаёт первый каталог ниже него как проект. Без него берётся родитель каталога изделия, пропуская служебные `G-test`, `export`, `exports`, `3d`, `html`. Имя модели берётся из B3D. В окне можно исправить проект и модель до отправки. Для структуры клиент/объект/изделие удобнее оставить `workRoot` пустым и проверить автоматически показанные имена.

## Android

Установить `Generator B3D.apk` (Android 8.0 и новее). В настройках указать `https://kb911.ru` и тот же ключ API. Ключ зашифрован AES-GCM с ключом Android Keystore. Резервное копирование приложения отключено; ключ отсутствует в APK.

Главный экран: проекты; внутри — модели с датой и размером, открытие ссылки в браузере, обновление, выбор до 100 моделей и удаление с подтверждением. После удаления последней модели проект исчезает автоматически. Android работает через API, без GitHub- или FTP-доступа.

## Контракт API

Все управляющие запросы требуют `Authorization: Bearer <MODELS_API_TOKEN>` и HTTPS. Redirect не считается успешной публикацией.

* `POST /api/models/upload?project=...&model=...`: готовые байты HTML, `Content-Type: text/html`, точный `Content-Length`, `X-Content-SHA256` (hex). Максимум 50 МиБ. Ответ: `success`, `url`, `sha256`, `size`, `updatedAt`.
* `GET /api/models/projects[?cursor=...]`: `projects: [{name}]`, `cursor` или null.
* `GET /api/models/project?project=...[&cursor=...]`: `files: [{project,model,size,updatedAt,url}]`, `cursor` или null.
* `DELETE /api/models/files`: JSON `{"files":[{"project":"...","model":"..."}]}`; от 1 до 100 записей. Повторное удаление безопасно. Пакетное удаление не является транзакцией; при сетевом сбое обновить список перед повтором.
* `GET/HEAD /3d-temp/<project>/<model>.html`: публичный HTML без изменения содержимого, с `no-store` и `X-Robots-Tag`. Списка каталогов нет. Ссылка доступна любому, кто её знает; это временное публичное хранилище, а не закрытый клиентский кабинет.

R2 проверяет SHA-256 при записи; файл публикуется целиком и заменяет предыдущий ключ. Папки — виртуальные префиксы, поэтому пустых папок не остаётся. Недопустимые пути и контрольные символы отклоняются.

## Проверка и сборка

`node --test tests/*.test.js` проверяет загрузку, замену, сохранность старого файла при плохой checksum, авторизацию, отсутствие списка каталогов, удаление и ограничения размера. До подключения реального R2 это проверки с моделью storage API, а не доказательство работы production deployment.

Android: JDK 17, Gradle 8.11.1, Android SDK 35 → `gradle assembleRelease`. Подписать собственным сохранённым ключом. Пароли/keystore не коммитить. Переданный APK подписан локальным приватным ключом, который сохранён на компьютере для следующих обновлений.

Перед выдачей клиентской ссылки провести сквозной тест реальной загрузки, повторной замены и чтения. Проверку на настоящем iPhone и Android отмечать отдельно: сборка APK не подтверждает работу на устройстве.
